IntelliRetrieve

Academic project · 2024–2025
View code
30% retrieval precision over TF-IDF baseline

A retrieval-augmented generation pipeline built to answer questions over large, unstructured document corpora instead of relying on an LLM's memory. Text goes through a full NLP preprocessing pass — tokenisation, stopword and punctuation removal, lemmatisation, whitespace normalisation, and spelling correction — before being chunked and embedded with the multi-qa-mpnet sentence-transformer model. Embeddings are indexed for cosine-similarity top-k retrieval, benchmarked on latency and throughput per query, with Pinecone in production and FAISS/Qdrant evaluated as lighter or larger-scale alternatives. A Flan-T5 encoder-decoder model generates the final answer — encoder self-attention and feed-forward layers build context, a masked-attention decoder produces the grounded response.

Preprocess→ Embed (multi-qa-mpnet)→ Vector store→ Top-k retrieval→ Flan-T5 generation

Scalable ETL pipeline

Academic project · 2024
View code
40% faster processing across 10M+ records

Built to bring order to roughly 10 million customer transaction records arriving in inconsistent formats — CSV from sales terminals, JSON logs from mobile apps, and Parquet from web activity logs — this pipeline uses a factory-method pattern in PySpark to route each format to the right reader without duplicating logic. The transform stage handles null removal, timestamp normalisation, and encoding fixes, then applies groupBy and broadcast joins for aggregation, plus window functions to compute per-user and per-session activity metrics used for downstream filtering. Results are loaded into Delta Lake, partitioned by region and month for faster queries, with checksum validation and controlled shuffle sizing to keep large joins stable, and ACID transactions plus time-travel to support safe reprocessing — feeding straight into analyst KPI dashboards and QA review.

Extract (CSV/JSON/Parquet)→ Transform (clean, join, window fn)→ Load (Delta Lake, partitioned)

E-Vault

Academic project · 2023–2024
View code
Client-side AES-256, hash anchored on-chain

A decentralised alternative to tools like Google Drive for data that needs an audit trail — built with use cases like patient records, legal documents, and contracts in mind. A React.js frontend integrates MetaMask as both the crypto wallet and the gateway into the app, handling signing, sending transactions, and network switching. Files are encrypted client-side with AES-256 before upload; the encrypted content lives in MongoDB via a Node.js backend, while a hash of the file plus metadata (timestamp, sender address) is written to an Ethereum smart contract — a self-executing agreement where sending ETH triggers the logic that releases the data. On retrieval, the system checks the connected MetaMask wallet, verifies the signature against the on-chain hash, and only then fetches and decrypts the file — keeping the expensive, permanent record on-chain small while the actual content stays off-chain.
